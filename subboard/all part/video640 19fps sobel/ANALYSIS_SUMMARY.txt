================================================================================
                              发现的关键问题
================================================================================

1. 致命缺陷：wr_done信号永远保持为1
   ├─ 位置：app_wrrd.v 第149行
   ├─ 原因：条件 `if(wr_done & !App_wr_en)` 持续匹配
   ├─ 后果：读取被永久阻塞
   └─ 影响：性能下降到接近0

2. 参数错误：延迟时间过长
   ├─ 当前：50,000周期 ≈ 1毫秒
   ├─ 参考：1,000周期 ≈ 20微秒
   ├─ 倍数：增加50倍！
   └─ 影响：每帧多延迟1毫秒

3. 逻辑缺陷：读取条件不完整
   ├─ 缺少：rd_done检查
   ├─ 问题：可能多次启动读取
   └─ 后果：缓冲溢出

4. 架构问题：缺乏读写互斥机制
   ├─ 参考代码都有明确的互斥
   ├─ 当前代码：无
   └─ 风险：理论上可能同时读写

  实际预期：10-15 FPS（考虑其他限制）

性能提升倍数：从0.9到10+ → 11倍以上！

优先级1 - 致命缺陷修复（必须做）：

  1. 修复wr_done逻辑（行149, 169）
     当前：else if(wr_done & !App_wr_en) { wr_done <= 1'b1; }
     修改：删除此分支，在else中清除wr_done
     预期：wr_done变成1周期脉冲，读取能够开始

  2. 调整延迟参数（行186）
     当前：sdr_rd_delay < 20'd50000
     修改：sdr_rd_delay < 16'd1500
     预期：延迟从1毫秒减少到30微秒

优先级2 - 重要逻辑修复：

  3. 添加rd_done检查（行248, 253, 258, 262）
     当前：缺少 !rd_done 条件
     修改：添加 !rd_done & 到条件中
     预期：防止多次启动读取

  4. 调整缓冲阈值（行248, 253, 258, 262）
     当前：udp_wrusedw < 'd3500
     修改：udp_wrusedw < 'd2048
     预期：匹配参考值，避免缓冲溢出

================================================================================
                          关键信号说明
================================================================================

写入相关：
  • App_wr_en      - 写入使能信号，直接来自wr_fifo_rd_en
  • App_wr_addr    - 写入地址（w_addr_cnt）
  • w_addr_cnt     - 内部地址计数器，0到307199循环
  • wr_done        - 一帧写入完成标志（应为脉冲）
  • wr_frame_cnt   - 写入帧计数器

读取相关：
  • App_rd_en      - 读取使能信号（app_rd_en_reg）
  • App_rd_addr    - 读取地址（r_addr_cnt）
  • r_addr_cnt     - 内部读取地址计数器
  • rd_done        - 一帧读取完成标志
  • rd_frame_cnt   - 读取帧计数器

控制相关：
  • sdr_rd_delay   - 写后延迟计数器（当前50000，应为1500）
  • frame_available - 帧可用标志（wr_frame_cnt != rd_frame_cnt）
  • Sdr_busy       - SDRAM控制器繁忙标志
  • Sdr_init_ref_vld - SDRAM刷新中标志

调试相关：
  • burst_sdr_rd_cnt - 突发计数器（0-3）
  • udp_wrusedw      - 网络侧缓冲使用
