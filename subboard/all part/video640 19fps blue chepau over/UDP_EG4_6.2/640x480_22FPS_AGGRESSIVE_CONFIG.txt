性能分析
================================================================================

### 处理时间详细计算

#### 1. SDRAM写入时间
```
像素数量: 307,200
有效写速率: 125MHz / 4 = 31.25MHz
写入时间: 307,200 / 31.25MHz = 9.83ms
```

#### 2. 读取延迟（激进优化）
```
延迟周期: 2500 @ 125MHz
延迟时间: 2500 / 125MHz = 20μs = 0.02ms
节省: 相比之前(40μs)节省20μs
```

#### 3. SDRAM读取时间（激进流控）
```
理论读取: 9.83ms
UDP流控影响: × 1.85倍（激进优化）
实际读取时间: ~18.2ms
节省: 相比之前(20.6ms)节省2.4ms
```

#### 4. 总处理时间
```
总处理 = 写入 + 延迟 + 读取
      = 9.83ms + 0.02ms + 18.2ms
      = 28.05ms
```

### 安全系数评估

```
帧间隔: 45.45ms
处理时间: 28.05ms
安全系数: 45.45 / 28.05 = 1.62x ✅

安全余量: 45.45ms - 28.05ms = 17.40ms
```

**评估结果**: ⭐⭐⭐⭐ **推荐配置**
- ✅ 安全系数1.62x，良好范围
- ✅ 17.4ms余量可应对性能波动
- ⚠️ 流控阈值较高，需监控FIFO状态
- ⚠️ 延迟较短，需验证SDRAM刷新时序

================================================================================
风险评估与注意事项 ⚠️
================================================================================

### 高风险因素

#### 1. UDP流控阈值 (3980/4096 = 97.2%)
**风险**: 仅2.8%余量，接近FIFO上限
**影响**: 如果以太网传输稍有延迟，FIFO可能溢出
**监控**:
- 必须监控udp_wrusedw信号
- 如果频繁达到3980，降低阈值到3950

#### 2. 读取延迟 (2500周期 = 20μs)
**风险**: 延迟时间减半，可能不足以完成SDRAM auto-refresh
**影响**: 可能导致SDRAM数据不稳定
**监控**:
- 观察是否有图像噪点或错误
- 检查是否有数据错误

#### 3. 安全系数 (1.62x)
**风险**: 虽然在良好范围，但余量有限
**影响**: 对性能波动敏感
**监控**:
- 长时间运行测试（2小时+）
- 压力测试（复杂场景）

### 建议的回退方案

如果出现不稳定，按以下顺序回退：

**优先级1: 降低流控阈值**
```verilog
'd3980 → 'd3950  // 恢复到3950
```
- 风险最低的回退
- 可能损失1-2fps

**优先级2: 增加延迟时间**
```verilog
20'd2500 → 20'd3500  // 部分恢复
```
- 如果仍有问题，恢复到5000

**优先级3: 降低帧率**
```verilog
13'd891 → 13'd1030   // 降到20fps
```

8. **帧率测试**

9. **网络质量**
   - UDP包丢失率应为0
   - 测试不同网络环境
   - 验证长距离传输

================================================================================
故障排查指南
================================================================================

### 症状1: UDP FIFO频繁满（full_flag触发）
**原因**: 流控阈值3980太高，以太网发送不及时
**解决**:
```verilog
// app_wrrd.v 行248,253,258,262
'd3980 → 'd3950  // 降低阈值
```
**预期**: 帧率可能略微降低到21fps，但更稳定

### 症状2: 图像出现噪点或数据错误
**原因**: 延迟2500周期可能不足，SDRAM刷新冲突
**解决**:
```verilog
// app_wrrd.v 行186,248,253,258,262
20'd2500 → 20'd3500  // 增加延迟到28μs
```
**预期**: 处理时间增加0.8ms，安全系数提升

### 症状3: 系统不稳定，间歇性错误
**原因**: 安全系数1.62x偏低，处理时间波动超出余量
**解决1**: 降低到20fps
```verilog
// UDP_Example_Top.v 行183
13'd891 → 13'd1030  // 20fps
```
**解决2**: 组合回退（流控+延迟）
```verilog
'd3980 → 'd3950     // 流控
20'd2500 → 20'd3500 // 延迟
```

### 症状4: 编译时序不满足
**原因**: 激进优化可能导致时序路径变长
**解决**:
1. 检查时序报告中的关键路径
2. 考虑降低帧率到20fps
3. 或回退到18fps配置
