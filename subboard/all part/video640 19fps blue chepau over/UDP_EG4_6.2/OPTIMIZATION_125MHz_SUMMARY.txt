## 背景分析

经过探索发现：
1. ✅ 当前工程的SDRAM时钟已经是125MHz（通过clk_pll配置）
2. ✅ Anlogic官方参考工程也使用125MHz SDRAM时钟
3. ⚠️ 性能瓶颈不是时钟频率，而是流控策略和延迟参数

## 优化方案：优化流控与延迟参数

### 目标
- 当前帧率：15fps @ 480×320
- 目标帧率：25fps @ 480×320
- 期望达到：更高的数据吞吐效率

================================================================================
修改详情
================================================================================

### 文件: /home/ysara/Desktop/video1/UDP_EG4_6.2/source_code/rtl/sdr/rtl/app_wrrd.v

#### 修改1: 减少SDRAM读取延迟（行186）

**修改前:**
```verilog
// 修改：延迟时间50000（1ms@50MHz），在性能和稳定性之间平衡
else if(wr_done & sdr_rd_delay < 20'd10000)
```

**修改后:**
```verilog
// 优化：延迟时间5000周期（40μs@125MHz），提升读取效率
else if(wr_done & sdr_rd_delay < 20'd5000)
```

**影响:**
- 延迟从80μs减少到40μs（节省40μs）
- 在125MHz时钟下，5000周期 = 40μs
- 这是保守但安全的优化值

#### 修改2: 提高UDP流控阈值（行248、253、258、262）

**修改前:**
```verilog
(udp_wrusedw < 'd3500)
```

**修改后:**
```verilog
(udp_wrusedw < 'd3900)
```

**影响:**
- UDP发送FIFO允许填充更多数据（从3500提升到3900 words）
- SDRAM读取可以更激进地进行，减少等待时间
- 预计可节省2-3ms的读取等待时间

#### 具体修改位置:
- 行248: SDRAM读取初始条件
- 行253: SDRAM读取突发中间条件
- 行258: SDRAM读取突发结束条件
- 行262: SDRAM读取最后一个字条件

```
SDRAM写入:  153600 words ÷ 31.25MHz = 4.92ms
读延迟:     10000周期 @ 125MHz = 80μs
SDRAM读取:  ~16ms (含UDP流控等待)
总计:       ~21ms
```

#### 优化后（预期）:
```
SDRAM写入:  4.92ms (不变)
读延迟:     5000周期 @ 125MHz = 40μs (节省40μs)
SDRAM读取:  ~13ms (流控优化节省3ms)
总计:       ~18ms (提升14%!)
```
