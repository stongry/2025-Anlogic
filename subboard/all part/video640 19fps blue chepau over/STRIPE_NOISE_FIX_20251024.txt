====================================================================
视频条状噪点问题修复 - UDP包大小不匹配
修复日期: 2025-10-24
====================================================================

【问题描述】
症状: "遍布全画面的条状噪点是和顶端1/5行相同的"
- 全画面遍布条状噪点
- 噪点颜色/内容与画面顶端96行 (61,440像素) 相同
- 每个UDP包都包含来自顶端96行的错误数据

【根本原因】
UDP包大小定义不匹配导致数据读取错误

====================================================================
【详细分析】
====================================================================

问题位置: /home/ysara/Desktop/video/UDP_EG4_6.2/source_code/rtl/sdr/rtl/app_wrrd.v:56

错误代码:
    assign UDP_PKT_BYTES = 16'd1536;  // ❌ 512 words * 3 bytes/word

正确值 (来自 UDP_Example_Top.v:171-172):
    localparam integer UDP_PKT_WORDS = 480;
    localparam integer UDP_PKT_BYTES = 1440;  // ✅ 480 words * 3 bytes/word

数学验证:
- **包大小差异**: 1536 - 1440 = 96 bytes/packet (32像素/包)
- **总像素数**: 640 × 480 = 307,200 pixels
- **总字节数**: 307,200 × 3 = 921,600 bytes (RGB)
- **包数量**: 921,600 ÷ 1440 = 640 packets/frame
- **累积错误**: 96 bytes × 640 packets = 61,440 bytes = 20,480 pixels
- **错误行数**: 61,440 ÷ 640 = **96 rows = 恰好 1/5 帧** ✅

这完全符合用户报告的症状!

====================================================================
【错误机制】
====================================================================

1. SDRAM读取逻辑 (app_wrrd.v) 认为每个UDP包需要 1536 bytes
2. 因此每次读取 512 个 RGB 像素 (512 × 3 = 1536 bytes)
3. 但UDP发送逻辑 (udp_loopback.v) 实际只发送 480 个像素 (1440 bytes)
4. 每个包多读的 32 像素 (96 bytes) 被丢弃或缓存
5. 由于FIFO和地址管理问题,这些多余数据来自帧的开头 (前96行)
6. 当FIFO下溢或时序错误时,这些旧数据被重复使用
7. 结果: 顶端96行的像素以条状形式散布在整个画面中

【时序分析 - Sdr_rd_en 与 Sdr_rd_dout】
====================================================================

检查结果:
- Sdr_rd_en 和 Sdr_rd_dout 来自加密的 SDRAM 控制器 IP (sdr_as_ram.enc.v)
- 无法直接查看内部时序
- 但根据 Anlogic SDRAM IP 文档,Sdr_rd_en 是数据有效信号
- 应该与 Sdr_rd_dout 对齐 (同周期有效)

潜在风险 (但不是主要问题):
- UDP_Example_Top.v:735 直接使用 Sdr_rd_en 作为 app_rx_data_valid
- 如果有多周期延迟,可能导致数据错位
- 但这不会产生"顶端96行重复"的特定模式
- **主要问题仍然是包大小不匹配**

【技术要点总结】
====================================================================

1. **UDP包大小的重要性**
   - 必须在整个数据路径中保持一致
   - app_wrrd.v、UDP_Example_Top.v、udp_loopback.v 都要对齐
   - 不匹配会导致数据累积错误

2. **症状分析方法**
   - "顶端1/5行重复" → 61,440 pixels = 96 rows
   - 96 bytes/packet × 640 packets = 61,440 bytes
   - 数学验证帮助定位根本原因

3. **数据路径完整性**
   - 摄像头 → FIFO → SDRAM → FIFO → UDP → 以太网
   - 任何一个环节的大小不匹配都会导致问题
