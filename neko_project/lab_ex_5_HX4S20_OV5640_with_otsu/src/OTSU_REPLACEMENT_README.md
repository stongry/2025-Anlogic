# OTSU算法替换说明文档

## 修改概述
已成功将 `video_delay.v` 模块中的 Sobel 边缘检测算法完全替换为 OTSU（大津法）自动阈值二值化算法。

## 主要修改内容

### 1. 信号定义更改
**删除的Sobel相关信号：**
- 行缓存器（line_buffer_0, line_buffer_1）
- 3x3滑动窗口（window[0:8]）
- Sobel梯度（gx, gy, gradient）
- 边缘检测结果（edge_result）
- 噪声消除相关信号
- 按键和阈值调整相关信号

**新增的OTSU算法信号：**
- 直方图统计：histogram[0:255] - 存储每个灰度级的像素数量
- 像素统计：total_pixels, sum_total
- OTSU计算：otsu_threshold, calc_gray_level
- 类间方差相关：variance_max, variance_between
- 权重统计：weight_background, weight_foreground
- 二值化结果：binary_result

### 2. 算法流程变更

**原Sobel算法流程：**
1. RGB → 灰度转换
2. 行缓存管理（需要2行缓存）
3. 构建3x3滑动窗口
4. Sobel卷积计算（Gx, Gy）
5. 梯度幅值计算
6. 阈值判断（需手动调整阈值）
7. 噪声消除
8. 输出边缘图像

**新OTSU算法流程：**
1. RGB → 灰度转换
2. 帧同步检测
3. 灰度直方图统计（统计每帧256个灰度级的像素分布）
4. OTSU阈值计算（最大类间方差法，自动确定最佳阈值）
5. 二值化处理（使用计算出的阈值）
6. 输出二值化图像

### 3. 核心算法原理

**OTSU算法（最大类间方差法）：**

类间方差公式：
```
σ² = (mG*p1 - m)² / (p1*(1-p1))
```

其中：
- p1 = 前景类的概率（像素数比例）
- m = 前景类的累加均值
- mG = 全图的平均灰度

算法遍历所有可能的阈值（0-255），选择使类间方差最大的阈值作为最佳二值化阈值。

### 4. 延迟链优化

**Sobel算法延迟：** 20级延迟（需要行缓存和窗口构建）
**OTSU算法延迟：** 6级延迟（只需灰度转换和二值化）

大幅减少了流水线延迟，提高了系统响应速度。

### 5. 资源使用对比

**Sobel算法资源：**
- 2个行缓存（2 × H_SIZE × 8bit）
- 9个窗口寄存器
- 大量乘法和加法运算
- 21级延迟寄存器

**OTSU算法资源：**
- 256个直方图计数器（256 × 20bit）
- 若干32位累加器
- 6级延迟寄存器
- 无需行缓存

### 6. 优势与特点

**OTSU算法优点：**
1. ✅ **自动阈值选择** - 无需手动调整阈值，算法自动确定最佳值
2. ✅ **适应性强** - 根据每帧图像的灰度分布自动调整
3. ✅ **计算简单** - 不涉及复杂的卷积运算
4. ✅ **延迟更小** - 只需6级延迟，响应更快
5. ✅ **适合文档处理** - 特别适合文字、二维码等高对比度场景

**OTSU算法限制：**
1. ⚠️ 要求直方图呈双峰分布（前景和背景灰度分布差异明显）
2. ⚠️ 对噪声敏感
3. ⚠️ 只能进行单阈值分割（二值化）
4. ⚠️ 不适合前景/背景比例悬殊的场景

### 7. 应用场景

**适合使用OTSU的场景：**
- 文档扫描和OCR预处理
- 二维码识别
- 车牌识别
- 印刷电路板检测
- 细胞计数和分析

**不适合使用OTSU的场景：**
- 需要保留灰度信息的场景
- 多目标、复杂背景的场景
- 边缘细节要求高的场景（此时Sobel更合适）

## 接口兼容性

模块接口保持不变，虽然按键和开关输入信号不再使用，但为了保持与上层模块的兼容性，这些端口仍然保留。

## 测试建议

1. 使用高对比度图像测试（如文档、文字）
2. 观察二值化效果是否清晰
3. 验证阈值自动适应性（改变光照条件）
4. 检查帧率是否满足要求

## 总结

成功将Sobel边缘检测替换为OTSU自动阈值二值化算法，代码结构清晰，无语法错误，可以直接用于FPGA综合和实现。新算法更适合需要自动二值化的应用场景，如文档处理、二维码识别等。
